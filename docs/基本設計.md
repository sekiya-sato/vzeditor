# VZ Editor 基本設計

## 目的

原作 [LZ Editor](https://github.com/TouryuTamane/lz-editor)（MIT License）の VZ 互換操作・2画面ファイラー・Markdown ビューを引き継ぎ、次を追加する。

- Windows 11 / Linux（Ubuntu 24 など）/ macOS の3 OS 対応
- 背面透過（背景）と文字透過（前景）を個別に調整
- 最前面固定
- 上記とフォントサイズの設定保存

## 確定事項

### 背面透過

- ウィンドウは常に透過可能（`with_transparent(true)`）で作成し、クリア色は完全透明にする。
- 透過するのは背景色のみ。文字・カーソル・行番号・ダイアログ・メニューのポップアップは不透明。
- 対象の背景: エディター本文・行番号欄・現在行・スクロールバー溝、Markdown ビュー、ファイラー全体、メニューバー、ステータスバー、バッファ帯、ファンクションキー欄。
- 不透明度は 20〜100%、10% 刻み。初期値 100%。

| 操作 | 内容 |
| :--- | :--- |
| `Alt+↑` | 背景を濃く（+10%） |
| `Alt+↓` | 背景を薄く（-10%） |
| `Alt+0` | 透過解除（100%） |
| メニューバー右端の `背 n%` | 左クリックで薄く（20% の次は 100% に戻る）、右クリックまたは Shift+クリックで濃く |
| メニュー「ツール」→「背景透過」 | 濃く / 透過 / 解除 |

### 文字透過

- 前景（文字・行番号・カーソル・ボタン類）の不透明度を背景とは別に 20〜100%、10% 刻みで変更する。初期値 100%。
- メニューバー・ステータスバー・バッファ帯・F キー欄・本文（エディター / Markdown / ファイラー）の内容に `Ui::multiply_opacity` を掛ける。各帯の背景は内容の外側（Frame）で塗るため影響を受けない。本文内で塗る背景は `bg_painter()` で文字透過の影響を外す。
- ダイアログ（ヘルプ・About・ファイラー操作）とメニューのポップアップは常に不透明。

| 操作 | 内容 |
| :--- | :--- |
| `Alt+Shift+「+」` | 文字を濃く（+10%） |
| `Alt+Shift+「-」` | 文字を薄く（-10%） |
| `Alt+Shift+0` | 文字透過の解除（100%） |
| メニューバー右端の `字 n%` | 左クリックで薄く（20% の次は 100% に戻る）、右クリックまたは Shift+クリックで濃く |
| メニュー「ツール」→「文字透過」 | 濃く / 透過 / 解除 |

「+」「-」は物理キーで判定する（US 配列 `=+`、JIS 配列 `;+`、JIS の Shift+「-」が `=` になる場合も「-」扱い）。

#### キーの重複確認

| キー | 用途 | 重複しない理由 |
| :--- | :--- | :--- |
| `Ctrl++` / `Ctrl+-` / `Ctrl+0` | フォントサイズ（原作） | Alt 併用時は反応しない |
| `Alt+P` | Markdown 切替（原作） | 文字・背景のキーは P を使わない |
| `Alt+T` / `Alt+↑↓0` | 最前面・背景 | Shift なしのときだけ反応 |
| `Alt+W` | 折り返し表示の切替 | Shift なしのときだけ反応。W はほかの Alt 系で使っていない |
| `Alt+S` / `Alt+O` | 上下分割の切替 / もう一方のペインへ | Shift・Ctrl なしのときだけ反応。S・O はほかの Alt 系で使っていない |
| `Alt+C` → `C` / `X` / `N` / `M` / `P` | Claude Code / Codex へ送信、Claude Code / Codex で新規セッション、GitHub Desktop で Push | C は透過・最前面のキーで使っていない。2打目は Alt+C の直後だけ有効（VZ 互換の Alt+P とも重ならない） |
| `Alt+Shift+「+」「-」0` | 文字 | Shift ありのときだけ反応 |
| `Alt+K` / `Alt+B` | ターミナル / 簡易ブラウザの切替 | Shift・Ctrl なしのときだけ反応。K・B はほかの Alt 系で使っていない（サクラの既定でも Alt+K・Alt+B は未使用） |

単体テスト `test_window_style_keys_do_not_overlap` で上記を確認する。Windows の言語切替（左 Alt+Shift のみ押して離す）は、間に「+」などを押すと発動しない。

### 最前面固定

- `Alt+T`、メニューバー右端の `TOP` ボタン、メニュー「ツール」→「最前面に固定」で切替。
- `ViewportCommand::WindowLevel(AlwaysOnTop / Normal)` を送る。起動時は保存値で `with_always_on_top()` を指定。

### ウィンドウの位置とサイズ

- 終了時に、外枠の左上（物理ピクセル）・内側のサイズ（論理ピクセル）・その時のモニターの拡大率・最大化を `settings.ini` に保存し、次回は前回のモニターの同じ位置で起動する。最大化中は元に戻したときのサイズを保存し、位置は最大化したモニター上に置く。最小化・全画面中は直前の値を保存する。
- 作成時の位置は主モニターの拡大率で換算されるため、起動直後のフレームで物理ピクセルの位置へ合わせ直す（`restore_window_position`）。拡大率の違うモニターでは一瞬ずれてから移動する。
- Windows では、保存した位置のタイトルバーがどのモニターの作業領域にも十分見えない場合（モニターを外した・配置を変えた後）、主モニターの中央に置く。macOS は OS が画面内に収め、Linux（Wayland）は位置を指定できない。
- 起動中のモニターの増減・拡大率の変更は OS と winit に任せる（外したモニター上のウィンドウは OS が残りのモニターへ移す）。

### 上下分割

- `F4` または `Alt+S`（両方式共通。F4 は修飾キーなしのときだけ）、メニュー「ツール」→「上下に分割」で、編集中のバッファを上下 2 つのペインで表示する。もう一度押すと解除。分割はバッファ（タブ）ごとで、設定には保存しない。巨大ファイルと Markdown ビューでは分割しない。
- ペインごとにカーソル・選択・スクロール位置を持つ。キー入力は操作中のペインに届き、もう一方のペインはキャレットを出さない。`Alt+O` か、もう一方のペインをクリックすると切り替わる。
- 境界をドラッグすると上下の高さを変えられる（各ペインは 2 行分以上を残す）。
- 境界はルーラー（高さはフォントサイズの 0.7 倍 + 6px、最低 16px）。操作中のペインの本文の桁に合わせ（横スクロールに追従）、1 桁ごとに目盛り、5 桁ごとに中の目盛り、10 桁ごとに長い目盛りと 10 の位の数字（0, 1, 2…）を描く。カーソルのある桁（全角・タブはその幅）に印を付ける。
- 実装（`split.rs`）: 操作中のペインの状態はバッファとスロットがそのまま持ち、もう一方の状態だけを `SplitView::other` に置く。描画では一時的に入れ替えて同じ描画処理（`paint_editor_pane`）で描く。もう一方のペインは編集に追従しない（範囲外になった位置は切り替え時に文書内へ収める）。

### 折り返し表示

- `Alt+W`（両方のキー割り当て共通）またはメニュー「ツール」→「長い行を折り返して表示」で切替。設定 `word_wrap`（`true` / `false`）に保存し、次回起動時に復元する。
- 折り返し幅はエディター表示域の幅（行番号・スクロールバーを除く）。文字幅を半角 1・全角 2・タブ 4 のセル数で数え、収まらない文字の前で折り返す（単語の区切りは考慮しない）。ウィンドウ幅やフォントサイズを変えると折り返し位置も変わる。
- 折り返した続きの表示行には行番号を出さず、改行マーク（↵）は論理行の最後の表示行にだけ出す。横スクロールはしない。
- ↑ / ↓（VZ 互換の Ctrl+E / Ctrl+X を含む）は表示行単位で移動し、左端からの見た目の位置を保つ。Home / End、PgUp / PgDn、行削除などは従来どおり論理行単位。
- 行割りはバッファごとに、テキストの版（revision）と幅が同じ間は使い回す。Markdown ビューは従来どおり（ビュー側で折り返す）。

### キー割り当て（サクラ互換 / VZ 互換）

- エディター画面のキー割り当てを「サクラ互換」と「VZ 互換」から選ぶ。既定（設定ファイルが無いとき）はサクラ互換。
- 切替: メニュー「ツール」→「キー割り当て: … へ切替」のみ（ステータスバーには表示しない）。設定に保存し、次回起動時に復元する。VZ 互換に切り替えると範囲選択は解除する。
- 2画面ファイラーのキー、Alt 系（透過・最前面・送信・Alt+P の Markdown 切替）、Ctrl+P（印刷）、エディターの Ctrl+F4（現在のバッファを閉じる）、F2（新規）、F3 / Shift+F3（次／前を検索）、Ins（挿入 / 上書きの切替）はどちらでも同じ。
- F4 はエディターでは上下分割の切替（両方式共通。F キー欄の表示は「分割」）。F5 は VZ 互換で行末（Markdown ビューでは末尾）、サクラ互換では割り当てなし（ステータスバーに未対応と表示）。
- 挿入 / 上書き: Ins で切り替える（両方式・メニュー「編集」）。起動時は挿入で、設定には保存しない。上書きでは文字入力と IME 確定がカーソル位置から入力文字数ぶんを置き換える（行末を越えた分は追加し、改行は消さない。選択中は選択範囲を置き換える）。貼り付け・Tab・Enter は上書きでも挿入。カーソルは挿入が文字幅の枠と縦棒、上書きが文字の下半分の塗りつぶし（どちらも点滅）。
- 下端の F キー欄（エディター・ファイラー）: F1〜F5・F6〜F10・F11〜F12 の 3 ブロック。12 個がボタンの最小幅（56px）で並ぶウィンドウ幅になると F12 まで表示し、それより広ければ幅いっぱいに広げる。狭いときは F10 まで。エディターの F11 は両方式とも特殊行コピー。F12 とファイラーの F11 は空欄。Shift・Ctrl（macOS は Cmd も）・Alt のどれか 1 つだけを押している間は、キー名を `SF1`〜`SF12`・`CF1`〜`CF12`・`AF1`〜`AF12` にし、その組み合わせの割り当てを表示する（クリックでもその動作。`FKeyLayer`）。2 つ以上の組み合わせ（Ctrl+Shift+F1 のバージョン情報など）は通常の表示。サクラ互換は SF3 前を検索・SF8 コピー・SF10 行の複製、CF3 検索ハイライト切替・CF4 閉じる、AF4 終了で他は空欄。VZ 互換は SF3 前を検索・SF4 は空欄（F4 の分割は修飾キーなしだけ）、CF3 検索ハイライト切替、AF3 は空欄、CF4 閉じる、AF4 終了で、F11 の修飾キー付きは空欄、ほかは通常の表示。2画面ファイラーは AF4（終了）以外を通常どおり表示する。
- F1 ヘルプは F1 / Esc でのみ閉じる（全モード共通。表示中の他のキーはエディター・シェルへ渡さない）。項目は画面の高さを超えると縦スクロール（ホイール・スクロールバー）する。
- About は、F1 / Esc / ×ボタンのほか、画面のどこをクリックしても閉じる（About のリンクのクリックは除く）。閉じるためのクリックは下のエディター・ファイラーに渡さない。
- サクラ互換の割り当ては利用中の `sakura.ini`（既定値）に合わせる。調査と全体の対比は [キー割り当て対比.md](キー割り当て対比.md)。

サクラ互換で実装済みのキー（段階1・2）:

| 分類 | キー |
| :--- | :--- |
| ファイル・バッファ | Ctrl+N / F2 新規、Ctrl+O 開く、Ctrl+S 上書き保存、Ctrl+Shift+S 名前を付けて保存、Ctrl+F4 閉じる（未保存なら確認）、Ctrl+Tab / Ctrl+Shift+Tab バッファ切替 |
| 編集 | Ctrl+Z 元に戻す、Ctrl+Y やり直し、Ctrl+X / Shift+Del / F7 切り取り、Ctrl+C / Ctrl+Ins / F8 コピー、Ctrl+V / Shift+Ins / F9 貼り付け、Del / BkSp、Ctrl+BkSp / Ctrl+Del 単語の左・右を削除、Ctrl+E 行切り取り、Ctrl+Shift+E 行削除、Ctrl+K（Shift）行末まで切り取り（削除）、Ctrl+U（Shift）行頭まで、Ctrl+D（Shift）単語、Ctrl+I / Shift+F10 行の二重化、Ins 挿入 / 上書きの切替 |
| 移動 | 矢印、Ctrl+← / → 単語、Home / End、Ctrl+Home / End ファイル先頭・末尾、PgUp / PgDn、Ctrl+PgUp / PgDn 半ページ、Ctrl+↑ / ↓ 1行スクロール |
| 範囲選択 | Shift+移動キー（Ctrl+Shift+← → Home End、Ctrl+Shift+↑ ↓ は2行ずつ）、Ctrl+A すべて選択、Ctrl+W 単語選択、F6 範囲選択開始（移動キーで選択を広げる）、マウスのドラッグ・Shift+クリック・ダブルクリック（単語）・トリプルクリック（行）、Esc 選択解除 |
| インデント | 選択中の Tab で選択にかかる各行の先頭に TAB を追加、Shift+Tab で先頭の TAB 1つ（無ければ空白4つまで）を削除（両方式。終点が行頭の行は含めない。選択なしの Tab は TAB 文字の挿入） |
| 表示・その他 | F1 ヘルプ、Ctrl+Shift+F1 バージョン情報、Ctrl++ / Ctrl+- / Ctrl+0 / Ctrl+ホイール フォントサイズ、Esc 2画面ファイラー（選択中は解除が優先）、Ctrl+Shift+V / Alt+P Markdown 編集 / ビュー切替、Ctrl+P 印刷 |

- ダブルクリック（単語）・トリプルクリック（1行）の選択は VZ 互換でも使える。カーソルは選択の先頭に置き、選択の終端（次の行など）へは動かさない。
- 選択中の文字入力・貼り付け・Enter・Del・BkSp は選択範囲を置き換える（アンドゥは1回で戻る）。
- 自動インデント（両方式共通）: Enter（VZ 互換は Ctrl+M も）は改行し、元の行の行頭の空白（タブ・半角スペース。全角スペースは対象外）をそのままの並びで新しい行の先頭に入れる（`TextBuffer::insert_newline_with_indent`）。カーソルが行頭の空白の途中ならカーソルより前の分だけ。選択中は選択範囲を消してから残った行を見る。Shift+Enter はインデントを入れず行頭から始める（`insert_newline`）。貼り付け・IME 確定の文字列に含まれる改行にはインデントを入れない。アンドゥは改行とインデントを1回で戻す。
- 切り取り・コピーは選択が無ければ現在行（改行を含む）が対象（サクラの「選択なしでコピー / 切り取り」と同じ）。
- サクラ互換の検索・置換・Grep・行ジャンプは Ctrl+F / R / G / J。両方式共通の Alt+F / R / G / J と検索メニューからも開く。次を検索は F3 または Alt+N、前を検索は Shift+F3 または Alt+Shift+N。検索・置換ダイアログでも F3 / Shift+F3 で次／前を検索する。
- 検索語は検索・置換・Grep で履歴を共有し、置換後の文字列と Grep の検索場所は個別に記録する。履歴はウィンドウごとに直近50件を保持し、各入力欄が空のときに ↑ で新しい順に呼び出し、↓ で空欄まで戻る。呼び出した値を編集すると履歴の移動を終了する。
- 検索条件は `vz-core::search` で行単位に評価し、エディターと Grep で単語単位・大小文字・正規表現の判定を共用する。検索結果はバッファの選択範囲に変換し、該当行マークはバッファの変更時に無効にする。検索を実行した条件は `SearchState::highlight` に残す。検索・置換ダイアログから検索を実行すると表示をオンに戻し、エディターの「次を検索」「前を検索」では表示状態を引き継ぐ。検索ハイライトの表示は両方式の Ctrl+F3 と検索メニューで切り替え、オン / オフは全タブで共通とする。オンのときだけ描画時に表示中の行（巨大ファイルは読み込んだ窓の文字列）だけを照合して一致箇所の背景を `SEARCH_HIT_BG` で塗る（空一致は塗らない。選択範囲はその上に描く）。
- 置換は現在の一致（置換後は次の一致を選択する。置換位置の空一致は飛ばす）、またはファイル全体／現在の選択範囲の一致を対象にする。一括置換は TextBuffer の履歴を1つ追加する。指定行ジャンプの折り返し単位には描画と同じ WrapLayout を使う。
- Grep は `vz-core::grep` で保存済みの UTF-8 ファイルを走査する。表示は最大2,000件で、対象・除外名のパターンを指定できる。処理は別スレッドで実行し、結果からエディター内の該当位置へ移動する。
- F11 の特殊行コピーは両方式共通。カーソル行の先頭から最後の半角 `.` の手前までをコピーし、`.` がなければ行全体をコピーする。改行は含めない。「編集」メニューからも実行できる。
- 未対応のサクラのキー（Shift+F2、F10、F12 など）は、ステータスバーに未対応と表示する。
- 制約: egui は Ctrl+Shift+V を貼り付けとして届けるため、クリップボードが空のときは Markdown 切替が反応しない（メニューか Alt+P を使う）。

### Claude Code / Codex への送信

vz で書いた指示を、起動中の Claude Code / Codex のデスクトップアプリへ送って送信する。

| 操作 | 送信先 |
| :--- | :--- |
| `Alt+C` → `C` | Claude デスクトップアプリ（Claude Code） |
| `Alt+C` → `X` | Codex デスクトップアプリ |
| `Alt+C` → `N` | Claude デスクトップアプリ（本文は送らず、Ctrl+N で新規セッション） |
| `Alt+C` → `M` | Codex デスクトップアプリ（本文は送らず、Ctrl+N で新規セッション） |
| `Alt+C` → `P` | GitHub Desktop（本文は送らず、表示中のリポジトリを Push） |
| メニュー「ツール」→「他アプリ連携」→「Claude Code へ送信」「Codex へ送信」「Claude Code で新規セッション」「Codex で新規セッション」「GitHub Desktop で Push」 | 同上 |

- 送るのは現在のバッファ全体（末尾の空行は除く）。空なら送らない。送信後もバッファの内容は残し、フォーカスを vz に戻す。
- 2打目は Alt を押したままでも離してもよい。`C` / `X` / `N` / `M` / `P` 以外のキーを押すと取り消す。2打目のキー（取り消しも含む）は文字として入力せず、2打目待ちの間は IME を切る（IME が先に取った入力も捨てる）。2打目は Alt+C の直後だけ有効なので、VZ 互換の Ctrl+X などとは重ならない。
- 両アプリとも外部から入力欄へ文字を渡す API が無いため、キー操作で送る。
  1. Alt などの修飾キーと 2打目の英字キーが離されるのを待つ（修飾キーを押したままだと Ctrl+V が Ctrl+Alt+V に、英字を押したままだとキーリピートで Ctrl+M などになる。Windows のみ英字も待つ。3 秒で打ち切り）
  2. 対象アプリのウィンドウを探して前面にする
  3. クリップボードに本文を入れて貼り付け、送信キーを押す（Claude Code は Enter、Codex は Ctrl+Enter。macOS の Codex は Cmd+Enter）
  4. 元のクリップボード（テキストのみ）を戻し、vz を前面に戻す
- 処理は別スレッドで行い、結果（送信した文字数、またはエラー）をステータスバーに出す。
- GitHub Desktop（`Alt+C` → `P`）: GitHub Desktop を前面にして、メニュー「Repository」→「Push」のショートカット Ctrl+P（macOS は Cmd+P）を押し、vz を前面に戻す。対象は GitHub Desktop で表示中（カレント）のリポジトリで、vz で開いているファイルのリポジトリとは限らない。Push の結果（未公開ブランチの公開、リモートが先行している場合の案内など）は GitHub Desktop の画面で確認する。Windows は `GitHubDesktop.exe`、macOS はアプリ名 `GitHub Desktop`、Linux はウィンドウクラス `GitHub Desktop` で探す。
- 新規セッション（`Alt+C` → `N` / `M`）: 送信と同じ方法で Claude Code / Codex のウィンドウを探して前面にし、新規セッションのショートカット Ctrl+N（macOS は Cmd+N）を押して vz を前面に戻す。本文は送らない。セッションが開いたかは各アプリの画面で確認する。

| OS | ウィンドウの探し方 | 貼り付け・送信 |
| :--- | :--- | :--- |
| Windows | 実行ファイルで判定。Claude: `Claude.exe`、Codex: `OpenAI.Codex` パッケージ内の `ChatGPT.exe`（同名の ChatGPT アプリには送らない） | SendInput で Ctrl+V → Enter（Codex は Ctrl+Enter） |
| macOS | アプリ名 `Claude` / `Codex` を activate | osascript（System Events）で Cmd+V → Return（Codex は Cmd+Return）。アクセシビリティの許可が必要 |
| Linux（X11） | xdotool でウィンドウクラス `Claude` / `Codex` を検索 | xclip と xdotool で Ctrl+V → Return（Codex は Ctrl+Return）。Wayland は非対応 |

- 確認状況: Windows で Claude Code（Enter）と Codex（Ctrl+Enter）への送信をユーザーが確認済み。macOS（Cmd+Enter）と Linux は未確認。GitHub Desktop の Push は未確認（実際に Push されるため確認はユーザーが行う）。
- 制約: アプリ内のフォーカスが入力欄にあることが前提（前面化すると直前にフォーカスしていた要素に戻る）。Claude アプリは表示中のセッションへ送る。クリップボードの画像など、テキスト以外の内容は戻らない。

### 複数ファイルを開く・ドラッグ＆ドロップ

すべての経路を `open_paths()` に集約し、次の規則で開く。

- ファイルはそれぞれバッファで開き、最初に開いたファイルを表示する。既に開いているファイルは新しいバッファを作らず切り替えるだけにする。
- 起動直後の未編集の [無題] バッファは、最初に開いたファイルで置き換える。
- 開けなかったファイルはステータスバーに名前を出し、残りは開く。
- フォルダだけが渡された場合は、ファイラーでそのフォルダへ移動する。

| 経路 | 内容 | 対応 OS |
| :--- | :--- | :--- |
| ドラッグ＆ドロップ | ウィンドウへ複数ファイルをドロップ。ドラッグ中は「ドロップして n 個のファイルを開く」を重ねて表示 | Windows / macOS / Linux（X11） |
| 起動引数 | `vz a.txt b.md ...`。エクスプローラーで複数ファイルを `vz.exe` に重ねた場合も同じ。存在しないパスは新規ファイルとして開く | 全 OS |
| 開くダイアログ（ファイルメニュー、サクラ互換は Ctrl+O も） | 複数選択可（Windows: rfd、macOS: osascript の multiple selections、Linux: zenity `--multiple` / kdialog `--multiple`） | 全 OS |
| 2画面ファイラー | Space でマークした複数ファイルを Enter でまとめて開き、マークを解除する。マークが無ければ従来どおりカーソル位置を開く | 全 OS |

- 2画面ファイラーの左右の見出しでは、Windows のドライブパスと UNC パスから拡張パスの接頭辞を除き、区切りに `/` を使う。省略は表示用の変換後に行う。
- 2画面ファイラーの Shift+Enter は、カーソル位置のファイル（フォルダ）を vz で開かず、OS の関連付けで実行する（`vz-platform::shell::open_with_os`）。Windows は `ShellExecuteW`（既定の動詞。`\\?\` を外し、ファイルのフォルダを作業フォルダにする）、macOS は `open`、Linux は `xdg-open`。`..` とマークは対象外。結果（失敗時は理由）をステータスバーに出す。

- 保存ダイアログや確認ダイアログの表示中にドロップされた場合は開かず、ダイアログを閉じるよう案内する。
- Linux の Wayland は winit がドラッグ＆ドロップに未対応のため対象外。macOS で Finder の「このアプリケーションで開く」や Dock アイコンへのドロップ（Apple Event）は未対応。

### ファイル履歴・フォルダ履歴

- メニュー「ファイル」→「最近使ったファイル」「最近使ったフォルダー」（キーの割り当てなし。サクラ互換・VZ 互換で共通）。新しい順に先頭 36 件を `0`〜`9`・`A`〜`Z` のアクセスキー付きで並べ、サブメニューを開いた状態でそのキーを押すと開く。ファイルは `パス  [文字コード]` と表示し、このウィンドウで開いているファイルに印を付ける。フォルダーを選ぶと 2画面ファイラーの表示中の窓でそのフォルダを開く。無いファイルは開かずにステータスバーへ出す。文字コードは表示だけで、開くときは自動判定する。
- クリック・Enter・アクセスキーで履歴の項目を確定した時点で先頭へ移す。Delete は選択中の項目を履歴から削除する。削除後もサブメニューを開いたままにし、次の行（末尾の場合は前の行）を選択する。
- 記録の契機: ファイルを開いた（開いているファイルへの切替を含む）・保存した（名前を付けて保存・終了時の保存を含む）とき、そのファイルと親フォルダ。ファイラーでフォルダへ入った・親フォルダへ移った・フォルダを開いたとき、そのフォルダ。状態の復元（Shift 起動・リリース）で開き直したものは記録しない。
- 保存: 設定フォルダの `history.ini`（`[files]` に `文字コード<TAB>パス`、`[folders]` にパスを 1 行ずつ、新しい順）。ファイル・フォルダそれぞれ最大 100 件で、超えたら古いものから消す。同じパス（Windows・macOS は大文字小文字を区別しない）は先頭へ移す。パスは `\\?\` を外した絶対パスで、改行・タブを含むパスは記録しない。
- 全プロセス（複数ウィンドウ）で共通に持つ。更新時は `history.lock` で排他し、ファイルを読み直して変更を反映し、一時ファイルに書いてから置き換える。ファイルメニューを開くときにも読み直す。保存に失敗したときは、そのプロセス内の履歴に変更を反映してステータスバーに出す。処理は `vz-config::history`。

### 終了時の保存確認

- 未保存の変更（既存ファイルの修正、新規バッファへの文字入力）があるバッファが1つでもあれば、終了前に確認ダイアログを出す。未入力の新規バッファだけなら確認せずに終了する。
- 対象の終了操作: F10（ファイラー）、メニュー「ファイル」→「終了」、ウィンドウの×ボタン、Alt+F4、macOS の Cmd+Q。OS からの終了要求は `close_requested` を受けて `CancelClose` で止める。
- Alt+Shift+F4 は確認せずに状態を記録して終了する（次節「状態の記録と Shift 起動での復元」）。
- ダイアログには未保存のバッファ名を並べ、次の3択とする。

| ボタン | キー | 動作 |
| :--- | :--- | :--- |
| 保存して終了 | Enter / Y | パスのあるバッファを上書き保存し、無題のバッファは1つずつ「名前を付けて保存」を開く。すべて保存できたら終了 |
| 保存せず終了 | N | 変更を破棄して終了 |
| キャンセル | ESC | 終了しない |

- 保存ダイアログのキャンセルや保存エラーの場合は終了を中止し、ステータスバーに理由を出す。
- 保存ダイアログを開いている間に×ボタンが押された場合は終了せず、ダイアログを閉じるよう案内する。

### リリース時の保存・入れ替え・復元

Windows と Ubuntu WSL2 のリリーススクリプトは、配置先から起動したウィンドウをプロセス単位で引き継ぐ。配布物を差し替える前にテストとリリースビルドを終える。

1. スクリプトがリリース ID（32 桁の16進数）を作り、新ビルドの `--release-save-and-quit <ID> <PID...>` に対象を渡す。全 PID の監視が稼働していることを確認してから要求を出す。要求は `session/release/instances/<PID>/` の監視ファイルで渡し、PID が再利用された場合に前の要求を受け取らないよう起動ごとの識別値を照合する。
2. 対象の VZ は `session/release/batches/<ID>/.writing-<PID>/` に状態を書き、書き終えてから `<PID>/` に改名して終了する。名前のある未保存ファイルも編集内容を一時保存し、巨大ファイルは編集差分を記録する。元ファイルは上書きしない。状態を書けない VZ は開いたまま理由を表示する。スクリプトは全 PID の保存と終了を確認した場合に実行ファイルを原子的に交換する。
3. 配置先の `--release-restore <ID>` が旧 PID ごとにウィンドウを起動する。初回の画面描画後、状態の読み込みがすべて成功したウィンドウが自分の記録を削除する。異常終了・復元失敗・タイムアウトでは未完了の記録を保持する。同じ記録の並行復元はファイルロックで防ぎ、再実行時は残った記録だけを扱う。

- 各ウィンドウでバッファの順序、表示中のバッファ、カーソル位置、Markdown ビュー、ファイラーの左右のフォルダ、ウィンドウ位置とサイズを保存する。仮想デスクトップは対応 OS で記録・復元する。
- ターミナルは記録したフォルダでシェルを起動し、ブラウザはタブの順序・URL・選択を戻す。シェル内の実行中のコマンドや画面、ブラウザの履歴は引き継がない。
- 未対応の旧ビルドが対象に含まれる場合、終了要求を出す前に中止する。初回の移行と途中で失敗した場合の操作は [build.md](../build.md) を参照する。

### 状態の記録（Alt+Shift+F4）と Shift 起動での復元

詳細は [状態の保存と起動時復元詳細設計.md](状態の保存と起動時復元詳細設計.md)。

- Alt+Shift+F4（両方式共通。メニュー「ファイル」→「状態を記録して終了」）は、確認せずに状態を `session\saved\<pid>\` に記録して終了する。形式は更新用の `session.ini` と同じ。パスのある未保存ファイルも上書きせず、`unsaved` として一時保存する（文字コードと読み込み時のファイルの状態も記録する）。巨大ファイルは `huge-edits`。モーダル表示中も受け付け、Windows で OS の閉じる要求として届いた場合も、Alt と Shift が押されていれば同じ扱いにする。
- 記録できなければ終了しない（巨大ファイルの保存中・すべて置換の実行中を含む）。
- Shift を押して起動すると、記録を PID の小さい順に 1 つ戻し、そのフォルダを削除する。戻せなかった巨大ファイルの編集は、その項目だけ記録に戻す。Shift は Windows が `GetAsyncKeyState`、macOS が `CGEventSourceFlagsState`、Linux は起動後 1 秒までのフレームの修飾キーで判定する。
- ほかの終了では記録しない。他の vz の記録は消さない。
- 同時に起動した vz が同じ記録を取らないよう、`restoring-<pid>-<時刻>` への改名に成功した 1 つだけが受け取る。書き込みは `.writing-<pid>` で行い、終わってから `<pid>`（ふさがっていれば `<pid>-<k>`）へ改名する。
- ウィンドウ: 記録（Alt+Shift+F4・リリース）では `session.ini` に物理モニターの `monitor` 行（位置・サイズ・拡大率・最大化・モニター名）と、取得できたときだけその直後に仮想デスクトップの `desktop` 行（仕組み・ID・名前）を別々に書く。復元（Shift 起動・リリース）では記録の位置・サイズへ合わせ、表示後に 1 回だけ記録の仮想デスクトップへ移す（Windows: `IVirtualDesktopManager`、Linux X11: EWMH の `_NET_WM_DESKTOP`。macOS Spaces・Wayland は非対応）。仮想デスクトップを取得・移動できなければ、その情報を使わずに通常の保存・復元を続ける。表示中のデスクトップは切り替えない。リリース時は旧 PID ごとにウィンドウ状態を戻す。通常の起動では仮想デスクトップを移さない。仮想デスクトップは vz-platform の `virtual_desktop`（`VirtualDesktopManager`）で扱う。
- `session.ini` の一時保存の欄はファイル名だけを書き、`session.ini` のフォルダからの相対で読む。改行の欄は `改行[;文字コード[;更新時刻ns;長さ]]`（古い `0` / `1` も読む）。`unsaved` は元の文字コードも戻す。

### 外部でのファイル変更の検知

- エディターで表示中のバッファの更新日時とサイズを、読み込み・保存の時点の値と 1 秒ごとに比べる。変わっていれば「外部での変更」ダイアログで再読み込みするか尋ねる。ほかのバッファは表示してから調べる。
  - 「再読み込み」（Y）: ファイルを読み直す。カーソル位置は残す（行が減った場合は範囲内に収める）。vz の未保存の変更は破棄するが、「元に戻す」で読み込み前の内容に戻せる。
  - 「このまま」（ESC / N）: 読み込まない。同じ変更では再度尋ねない（さらに変更されたら尋ねる）。
- 表示直後 0.4 秒はキーで答えない（入力中の打鍵で誤って答えないため）。ダイアログ・メニュー・保存ダイアログを開いている間は調べない。
- vz 自身の保存は外部の変更として扱わない。削除されたファイル、未作成の新規ファイルは尋ねない。

### 文字コードと巨大ファイル

詳細は [巨大ファイル詳細設計.md](巨大ファイル詳細設計.md)。

- 文字コード: UTF-8・UTF-8 BOM・Shift_JIS（CP932）を判定して読み、同じ文字コードで保存する（`vz-core::encoding`）。表せない文字があれば保存せず、行・桁を知らせる。メニュー「ファイル → 文字コードを指定して保存...」とステータスバーの文字コードのクリックで、文字コードを選んで保存する（キーの割り当てなし）。
- 128MB（`HUGE_FILE_THRESHOLD`）以上は巨大ファイルモード（`vz-core::huge::HugeDoc`）。`TextBuffer` が中身を「行の配列」か `HugeDoc` のどちらかで持ち、画面側は同じ API（`line_count` / `line` / `line_segment` と既存の編集・移動の関数）で扱う。
  - 元ファイルは memmap2 で読み取り専用に対応付け、追加した文字は 1MB の追加ブロック（追記だけ）に置き、文書をピースの並びで表す。並びは B-Tree（Piece Tree。各節に ピース数・バイト数・改行数・未確定の数 の合計）で持つ（Crowley のピーステーブル）。
  - 行索引（1024 行ごとの行頭位置）は裏のスレッドで並列に作る。索引ができた範囲はすぐ表示・編集でき、範囲外にかかるピースは改行数を「未確定」にして、索引が届いたら入れる。
  - 変更は vis と同じ Change（位置・外したピース・入れたピース）のまとまりで記録し、Undo / Redo はピース列の入れ替え（200 回まで）。続けて入力した文字は 1 つのピースを伸ばす。
  - 保存は裏のスレッドで同じフォルダの一時ファイルへ順に書き出し（文字コードの変換もここ）、rename で置き換える。元ファイルの対応付けは外さないので、保存後も Undo できる（Windows でも確認）。保存中・置換中は編集できず、外部変更の検知もしない。
  - 検索（次・前）・すべて置換・Grep は行の境界にそろえた 4MB のチャンクを並列に調べる。すべて置換は結果を作業ファイル（`.<名前>.vzwork-….tmp`）に書き出して 1 ピースに入れ替え、使われなくなったら消す。
  - 表示は画面に入る範囲（窓）だけを読み、横スクロールは文字単位。縦位置は f64（1 億行でも精度が足りるように）。
  - 折り返し表示は、先頭に表示している (論理行, 表示行) から画面に入る分だけを折り返す（`HugeWrapCache`。長い行は 1,024 表示行ごとの開始位置を覚える）。スクロールバーは論理行の割合。
  - 実行中の検索・すべて置換・索引待ちの行ジャンプは Esc で中止する。すべて置換の結果をそのまま保存するときは作業ファイルを rename する。ハードリンクのあるファイルは、通常の保存と画面の「保存して終了」で置き換え前に確認する（`vz-platform::file_info`）。
  - リリース時と Alt+Shift+F4 は、未保存の巨大ファイルの編集内容を `huge-<pid>-<n>.vzedit` に一時保存する。一時保存に失敗した場合は理由を表示して終了を中止する。復元時はこの編集内容を当て直す（`EntryKind::HugeEdits`）。
  - mmap できなければ 2GB 以下はメモリに読み込む（`Backing::Heap`）。索引の作成中だけ `Mmap::advise(Sequential)`（Linux / macOS）。
  - 巨大ファイルでは Markdown ビュー・行マーク・バッファ全体の送信は使わない。

### ターミナル（Alt+K）

- `Alt+K`（両方式共通）またはメニュー「ツール」→「ターミナル」で、エディター / ファイラーとターミナル画面を切り替える。もう一度押すと切り替える前の画面へ戻る。画面の状態（`AppMode::Terminal`）とシェルはアプリ内に 1 つ。
- ターミナルは最大 1 つ、ブラウザはタブで複数。一度開くと、バッファ帯（ファイルが 1 件でも表示）のファイルのタブの後ろに「ターミナル」・「ブラウザ:ページのタイトル」（ブラウザのタブが複数なら「ブラウザ1:…」「ブラウザ2:…」）のタブを並べる。タブのクリックでその画面へ、ファイルのタブのクリックでエディターのそのバッファへ切り替える。ファイラーではバッファ帯を出さない。
- ファイルタブを別のファイルタブへドラッグすると、ドロップ時にファイルの順序を更新する。タブ番号・キーでの切替・セッション保存はその順序を使い、表示中のバッファは維持する。
- Windows・macOS・Linux X11 では編集ファイルが 1 個でもファイルタブを表示し、ウィンドウ外へドロップすると別プロセスに移動する。カーソル直下に同じ設定フォルダの VZ があればそのプロセスに渡し、その他の領域なら新しい VZ を起動する。Wayland ではウィンドウ内の並べ替えが使える。
- プロセス間の引き継ぎは設定フォルダの一時データを使う。本文、未保存状態、ファイル名、文字コード、改行、カーソル位置、Markdown ビュー状態を復元する。Undo / Redo の履歴は移動先で作り直す。巨大ファイルは元ファイルと編集差分を使って開き、すべて置換の作業ファイルを含む場合は本文を一時ファイルへ順次書き出す。受け取りが確認でき、移動中に元の内容が変わっていない場合にだけ元タブを閉じる。同じファイルが開かれている場合は移動を拒否する。
- 編集対象・ターミナル・ブラウザのいずれかがあったウィンドウは、最後の対象がなくなると終了する。未入力の無題タブは対象に数えない。空の状態で起動した場合は初回の入力やファイルを開く操作を待つ。
- 名前のあるファイルのタブをダブルクリックすると、拡張子付きのファイル名をクリップボードへコピーする。
- シェルは初めて表示したときに起動し、画面を切り替えても動かし続ける（出力は毎フレーム取り込む）。作業フォルダは、編集中のファイルのフォルダ、無題ならファイラーのアクティブな窓のフォルダ（ファイラーから開いたときはその窓）。
- シェル: Windows は WSL2 の既定のディストリビューション・既定のシェル（`%SystemRoot%\System32\wsl.exe --cd <フォルダ>`）。wsl.exe が無ければ Git Bash（`bash --login -i`、`CHERE_INVOKING=1`）、PowerShell の順。Linux / macOS は bash（無ければ `$SHELL`、`/bin/sh`）。環境変数 `VZ_TERMINAL_SHELL` があればそれを使う。`TERM=xterm-256color`・`COLORTERM=truecolor`（WSL へは `WSLENV` で渡す）。
- 端末: PTY は portable-pty（Windows は ConPTY）、画面モデルは vt100（スクロールバック 5000 行、256 色・RGB、太字・下線・反転、全角の 2 桁幅）。DSR（`ESC [ 6 n` など）にはカーソル位置を返す。描画の行数・桁数はパネルの大きさとフォントサイズから決め、変わったら PTY も合わせる。
- キー: Alt 系の共通キー（透過・最前面・折り返し・送信・Alt+K / Alt+B）を除き、すべてシェルへ送る。文字・IME の確定文字はそのまま、矢印・Home / End・F キーなどは xterm のエスケープシーケンス（DECCKM 対応、修飾キーは `CSI 1;m`）、Ctrl+文字は制御コード、Alt+文字は ESC を前置。egui がコピー・切り取り・貼り付けに変える Ctrl+C / Ctrl+X は `0x03` / `0x18` として送り、Ctrl+Shift+C は選択範囲（無ければ見えている画面）の文字をコピーする（macOS は Cmd+C がコピー）。貼り付けは bracketed paste に対応し、改行は CR にする。
- マウス選択: 左ボタンを押してドラッグし、離した時点で範囲（押したセルから離したセルまで、行をまたぐときは途中の行全体）を確定してクリップボードと内部クリップボードへコピーする。行末の空白は除き、折り返した行はつなげる。選択は表示中の画面の位置で持つので、キー入力・貼り付け・ホイールでのスクロール・画面サイズの変更・クリックで解除する。
- マウスホイールで履歴を表示し、キー入力で最新へ戻る。範囲選択・マウスでのコピーは未対応。
- `exit` などでシェルが終了したら、ターミナルを閉じて（タブも消す）元の画面へ戻り、ステータスバーに終了コードを出す。次の Alt+K で新しく起動する。アプリの終了時はシェルを終了させる。
- 背景は `bg()` / `bg_painter()` で背面透過に従い、文字は文字透過に従う。F キー欄は表示しない（F キーはシェルへ送る）。

### 簡易ブラウザ（Alt+B）

- `Alt+B`（両方式共通）またはメニュー「ツール」→「ブラウザ」→「編集中の HTML を表示」で切り替える。もう一度押すと元の画面へ戻る。
- エディターで HTML・SVG（`.html` `.htm` `.xhtml` `.svg`）を編集中に `Alt+B` を押すと、そのファイルを `file:///` で表示する。そのファイルを表示中のタブがあればそのタブを選んで再読み込み、無ければ新しいタブで開く（選択中のタブが案内ページならそこで開く）。
- タブ: `Ctrl+T`（ツールバーの「+」、メニュー「ツール」→「ブラウザ」→「新しいタブ」）で案内ページの新しいタブ、`Ctrl+W`（「×」）で選択中のタブを閉じて WebView も破棄する。最後のタブを閉じたらブラウザを閉じて元の画面へ戻る。`Ctrl+Tab` / `Ctrl+Shift+Tab` で次 / 前のタブ（端で反対の端へ回る）。`target="_blank"` などの新しいウィンドウは新しいタブで開く。これらのキーはブラウザ画面だけで、サクラ互換・VZ 互換で共通。未保存の変更があれば、保存済みの内容を表示していることをステータスバーに出す。
- 画面上部に ← → 再読込・URL 欄・開く・編集中のファイル・外部ブラウザ。URL 欄はスキーム付きはそのまま、存在する絶対パスは file URL、`localhost`・IP アドレスは `http://`、ドメインらしいもの（`.` を含む）は `https://` を補う。それ以外は開かない。キーは `F5` 再読み込み、`Alt+←` / `Alt+→` 戻る / 進む。
- 実装: wry で WebView を親ウィンドウの子として作り（Windows: WebView2、macOS: WKWebView）、毎フレーム描画の後でパネルの位置（物理ピクセル）に合わせる。タブごとに WebView を持ち、初めて表示するときに作る。表示するのは選択中のタブだけで、ほかのタブは隠す（隠すとフォーカスが親へ戻るので、ほかのタブを先に隠してから選択中のタブを表示する）。隠れているタブのタイトル・URL も更新する。データ（Cookie・キャッシュ）は設定フォルダの `webview`。
- WebView は egui の上に重なるため、メニュー・ヘルプ・About・ダイアログ・パス入力・ファイルのドラッグ中は隠す。ページの部分は背景透過・文字透過の対象外。
- WebView は別ウィンドウなので、ページをクリックした後はキーがページへ行く。ページの外（URL 欄・タブ・メニューなど）をクリックしたら親ウィンドウへフォーカスを戻し、URL 欄に入力できるようにする。URL 欄に入力中はページの読み込みで URL 欄を書き換えない。ツールバーは右端のボタンを先に置き、URL 欄は残りの幅にする。
- ページにフォーカスがあると egui にキーが届かないので、ページに差し込むスクリプトで Alt+B / Alt+K とタブ操作（Ctrl+T / Ctrl+W / Ctrl+Tab / Ctrl+Shift+Tab）を拾い、IPC で vz に知らせる（`code` に加えて `keyCode` で判定）。隠すときはフォーカスを親ウィンドウへ戻す。
- Linux は対応しない（wry の WebView は GTK のウィンドウを要し、Wayland の winit ウィンドウに埋め込めない）。画面と URL 欄は使え、「外部ブラウザ」で既定のブラウザに開く。

#### Linux 対応の検討案（未実装）

| 方式 | 内容と改修範囲 |
| :--- | :--- |

### 印刷（Ctrl+P）

- 現在のタブのバッファ内容（未保存の変更を含む）を A4 縦 / 横で選んだプリンターへ印刷する。両方式とも Ctrl+P とメニュー「ファイル → 印刷...」（エディター画面のみ。Markdown ビュー中はビューの見た目のまま印刷する。下記）。Markdown 切替は両方式共通の Alt+P に移した（サクラ互換は Ctrl+Shift+V、VZ 互換は Ctrl+K→V も残す）。
- 確認ダイアログ（`FilerModal::ConfirmPrint`）に「印刷しますか？」・プリンターの選択（一覧）・用紙の向き・文字サイズ・ページ番号の有無・ページ数を出す。Y / Enter で印刷、N / Esc で取消、← / → で縦横、↑ / ↓ で本文の文字サイズ（8〜14pt、既定 10pt）、Space でページ番号の有無、A で印刷するページ（全ページ / 開始〜終了ページの指定。指定の初期値は 1〜総ページ数）、PgUp / PgDn でプリンターを切り替え（一覧を開いている間とページ番号の入力中はこれらのキーをそちらの操作に回す）。ページ指定は `PrintDoc::with_page_range` で `range` に持ち、ヘッダーのページ番号は全体の「n / m」のまま印字する。ページ数が変わったら指定範囲を総ページ数に収め直す。向き・文字サイズ・ページ番号を変えるたびにページ数を数え直して設定を保存する。表示直後 300ms の Y / Enter は受け付けない。最初に選ぶプリンターは、このプロセスで前回印刷したもの → OS の既定 → 一覧の先頭（`initial_printer`。settings.ini には保存しない）。
- 目安は 100 ページ（`PAGE_LIMIT`）。論理行数が 100 ページ分を超える、折り返しで 200 ページを超える、または巨大ファイルモードのときは「ファイルが大きすぎます」とし、印刷しない（ダイアログ表示中に設定を変えて超えた場合は印刷ボタンを無効にする）。プリンターが 1 つも無ければ「プリンターがありません」。
- 割付は `vz-core::print`（`layout`）: 余白は上下左右 7.5mm（プリンターの印字できない縁より広い）、ヘッダー欄 8mm（9pt）、行送りは文字サイズ × 1.4。半角 0.5em・全角 1em の升目に置き（unicode-width）、タブは画面と同じく空白 4 つに展開し、常に印字幅で折り返す（全角が端にかかれば次の行へ）。左に論理行番号（3 桁以上の右寄せ、折り返しの続きは空欄）、ヘッダーに左からファイル名（長ければ先頭を「...」）・印刷日時・「n / m」（ページ番号ありのとき）。10pt で縦は 110 桁 × 55 行、横は 159 桁 × 37 行。ページは `PrintPage::Lines`（行番号付きの行）か `PrintPage::Items`（文字列・矩形・線の図）。
- 出力は `vz-platform::print`（`printers` で一覧、`spawn_print` で裏のスレッド。結果はステータスバー）: Windows は GDI（`DocumentPropertiesW` で DEVMODE に A4・向きを設定。一覧は `EnumPrintersW`（ローカルと接続済み）、`ExtTextOutW` の文字送りで升目に置く。図のページは文字ごとの送り幅で置き、色は `SetTextColor`、矩形は `FillRect`、線はペンで引く。書体は画面と同じ優先順の日本語等幅フォント）。macOS / Linux は krilla で PDF を作り（日本語フォントは使った文字だけ埋め込む。横はページ自体を横にする。図のページは塗り・線のパスで描き、斜体は傾ける）、一時ファイルを `lp -d <選んだプリンター> -o media=A4` に渡して消す。一覧は `lpstat -e`、既定のプリンターは `lpstat -d`。
- Markdown ビュー表示中の印刷は `vz-ui` の `markdown/print.rs`（`layout_markdown_print`）で割り付ける。画面と同じ寸法比（基準は印刷の文字サイズ）で egui のレイアウト（`build_inline_job` を共用、精度のため 4 倍で割り付けて縮める）に通し、グリフの位置と送り幅をそのまま `PrintItem::Text` にする。見出しの罫線・表の枠と縞・コードブロックの背景と枠（言語名のラベル付き、長い行は折り返す）・引用の背景と縦棒・インラインコードの背景・リンクの下線・打ち消し線も矩形と線で描く。色は画面の配色を白い紙向けの配色（`PRINT_COLORS`）に置き換える。行番号は印字せず、ヘッダーはテキストの印刷と同じ。改ページは行（段落の折り返し行・コードの行・表の行）単位で、見出しは続く 2 行分が入らなければ次のページへ送る。100 ページを超えると「ファイルが大きすぎます」。割付には egui のフォントが要るので、アプリは `egui::Context` を持つ（`egui_ctx`）。
- 日本語フォントの候補探索（fontconfig・OS ごとの既定パス）は `vz-platform::fonts` に置き、画面（vz-ui の `fonts`）と印刷で共用する。

### 設定保存

| :--- | :--- |
| Windows | `%APPDATA%\vzeditor\settings.ini` |
| macOS | `~/Library/Application Support/vzeditor/settings.ini` |
| Linux | `$XDG_CONFIG_HOME/vzeditor/settings.ini`（未設定時 `~/.config/...`） |

### クレート構成（Cargo ワークスペース）

ルートのパッケージ `vzeditor`（実行ファイル `vz`）がワークスペースを兼ね、`crates/` の 6 つのライブラリを組み立てる。分けすぎないよう、クレートは依存の向きが違うときだけ分け、同じ層の中はモジュールで分ける。

| クレート | 役割 | 主なモジュール | 依存 |
| :--- | :--- | :--- | :--- |
| `vzeditor`（ルート） | 起動・引数処理・アイコン・exe リソース・配布設定（deb / rpm） | `main.rs` `icon.rs` `build.rs` | vz-ui ほか |
| `vz-ui` | 画面・メニュー・キー操作・Markdown ビュー・透過・フォント | `app/` `markdown` `window_style` `fonts` | 下の 3 つ・eframe |
| `vz-platform` | OS 固有処理（ダイアログ、クリップボード読み取り、モニターの作業領域、外部アプリへの送信、修飾キーの状態、仮想デスクトップ、日本語フォントの候補、印刷） | `dialog` `clipboard` `monitor` `send_to_app` `keyboard` `virtual_desktop` `fonts` `print` | vz-core（印刷の割付）・krilla（macOS / Linux の PDF） |
| `vz-config` | 設定と、保存して終了・復元の状態 | `settings` `session` | なし |
| `vz-core` | UI に依存しない編集モデル（バッファ・巨大ファイル・文字コード・検索・差分・ファイラーの操作・印刷の割付） | `buffer` `huge`（`tree` `index` `search`）`encoding` `search` `grep` `diff` `filer` `print` | memmap2・memchr・rayon・encoding_rs・regex |
| `vz-terminal` | 組み込みターミナル（PTY でシェルを起動、VT 出力の画面モデル、キーのバイト列、シェルの選択） | `lib`（`Terminal`）`keys` `color` `shell` | portable-pty・vt100 |
| `vz-browser` | 簡易ブラウザ（WebView の埋め込み・位置・表示、URL の正規化） | `lib`（`EmbeddedBrowser`） | wry（Windows / macOS）・raw-window-handle |

- 依存は上から下への一方向。vz-core・vz-config・vz-platform・vz-terminal・vz-browser は egui に依存しない（ターミナル・ブラウザの描画とキーの受け取りは vz-ui の `app/terminal_view.rs` `app/browser_view.rs`）。
- vz-terminal・vz-browser は OS ごとの処理（シェルの選択、WebView）を含むが、その機能だけで閉じるため vz-platform には置かない。
- 中身の無いクレートは作らない。構文ハイライト・LSP・独自 GPU 描画は、機能を作るときに要否を決める。全文検索・AI 連携・キー割り当ても、量が増えて独立させる理由ができたらクレートにする（それまではモジュール）。
- 版・ライセンス・リポジトリはワークスペースで共通（`workspace.package`）。ビルド日時 `VZ_BUILD_AT` は About を描く vz-ui の `build.rs` が埋め込み、ワークスペース内のソース変更で更新する。
- `cargo check` / `clippy` / `test` / `build` はルートで実行すれば全クレートが対象（`default-members`）。

`vz-ui` の `app/` は画面本体 `VzEditorApp` を役割ごとのファイルに分ける。

| ファイル | 内容 |
| :--- | :--- |
| `app/mod.rs` | 状態（`VzEditorApp`・`BufferSlot` など）、初期化、`eframe::App`、共通の補助関数 |
| `app/theme.rs` | 配色の定数 |
| `app/window.rs` | 文字サイズ、透過・最前面、ウィンドウ位置、設定の保存 |
| `app/wrap.rs` | 折り返し（`WrapLayout`）と表示行単位のカーソル移動 |
| `app/huge.rs` | 巨大ファイルの索引の取り込み、裏のスレッドでの保存・検索・すべて置換、ステータス表示 |
| `app/send.rs` | Claude Code / Codex / GitHub Desktop への送信 |
| `app/print.rs` | 印刷の確認ダイアログ・割付の呼び出し・裏のスレッドでの印刷 |
| `app/terminal_view.rs` | ターミナルの切替・キー入力の送信・描画 |
| `app/browser_view.rs` | 簡易ブラウザの切替・URL 欄・WebView の位置と表示の同期 |
| `app/keys.rs` | サクラ互換のキー処理と編集操作 |
| `app/function_keys.rs` | キー入力と画面のボタンが参照するファンクションキーの割り当て |
| `app/files.rs` | Markdown ビュー・ファイラーとの切替、バッファの切替、開く・保存・閉じる・終了 |
| `app/restore.rs` | セッションの読み書き、状態の記録（Alt+Shift+F4）・Shift 起動での復元 |
| `app/external_changes.rs` | 外部でのファイル変更の検知・再読み込みと、復元時に保留した競合の確認 |
| `app/menu.rs` | メニューの項目・実行・描画（「ツール」はブラウザ・フォント・背景透過・文字透過・他アプリ連携をサブメニューにまとめる。→ / Enter で開き、← / Esc で閉じる） |
| `app/input.rs` | VZ 互換のキー処理、エディター・ファイラーの操作 |
| `app/bars.rs` | ステータスバー、バッファ一覧、ファンクションキー表示 |
| `app/editor_view.rs` `app/filer_view.rs` | エディター・ファイラーの描画 |
| `app/dialogs.rs` | ヘルプ、About、ファイラーの確認画面、パス入力 |
| `app/tests.rs` | アプリのテスト |

- `vz-ui` の Markdown ビューは `markdown/parser.rs` で構文を解析し、`markdown/render.rs` で描画する。印刷は `markdown/print.rs`（画面の配色を印刷用に置き換える）。
- `vz-core` の `TextBuffer` は `buffer/` 内でカーソル移動・編集・履歴を分け、巨大ファイルのスナップショットと保存は `huge/snapshot.rs` に置く。
- `vz-config` の `session.rs` は記録内容の読み書きを担当し、`session/` 内で記録の公開・取得とリリース時の終了要求・復元を分ける。
- `vz-browser` は URL の正規化・変換を `url.rs` に置く。

## 配布（GitHub Release）

`.github/workflows/release.yml`: `v` で始まるタグ（例: `v0.1.0`）を push すると、各 OS でテスト・リリースビルドし、GitHub Release に公開する。手動実行ではビルドと成果物のアップロードまで（Release は作らない）。

| OS | ランナー | 成果物 |
| :--- | :--- | :--- |
| Linux x86_64 | ubuntu-latest | `vz-linux-x86_64`、`vzeditor_<版>_amd64.deb`、`vzeditor-<版>.x86_64.rpm` |
| Linux aarch64 | ubuntu-24.04-arm | `vz-linux-aarch64`、`vzeditor_<版>_arm64.deb`、`vzeditor-<版>.aarch64.rpm` |
| Windows x86_64 | windows-latest | `vz-windows-x86_64.exe` |
| macOS Apple Silicon | macos-latest | `vz-macos-aarch64`（署名なしの単体バイナリ） |

- すべての成果物の SHA256 を `SHA256SUMS.txt` にまとめる。
- .deb / .rpm の内容は `Cargo.toml` の `package.metadata.deb` / `package.metadata.generate-rpm`（`/usr/bin/vz`、`assets/vzeditor.desktop`、アイコン、README、LICENSE）。
- 版は `Cargo.toml` の `workspace.package.version`（全クレート共通）に合わせ、タグもそれに合わせる。

## 確認状況

- 巨大ファイル・文字コード: Windows 11 実機で、10GB（9,860 万行）のファイルの表示（約 0.2 秒）・索引（数秒）・末尾へのジャンプ・入力と改行・50MB の行の横スクロール・検索・Grep（131 件）・すべて置換と Undo・保存と保存後の Undo、Shift_JIS のファイルの編集・保存と UTF-8 での保存を確認。WSL2 では 64 GiB 級ファイルと終了時のハードリンク保護を確認した。結果は [巨大ファイル詳細設計.md](巨大ファイル詳細設計.md#13-wsl2-での-64-gib-級ファイルの検証) を参照。ネイティブ Linux と macOS の画面操作は未確認。

- release.yml は YAML の構文と Cargo.toml のメタデータの読み込みまで確認。GitHub Actions での実行（特に Windows・macOS のビルドと .deb / .rpm の作成）は未確認。

- 印刷: Windows 11 で Microsoft Print to PDF への A4 縦・横の出力（GDI）と、PDF 生成（krilla）の内容を確認。Markdown ビューの印刷は Microsoft Print to PDF への出力（GDI、`tests/fixtures/markdown_sample.md`）で確認。Linux は型チェックと PDF 生成のテストのみ（`lp` での実際の印刷は未確認）。macOS は型チェックのみ。
- Windows 以外（macOS / Linux）の実機での透過・最前面の動作は未確認。Linux はコンポジタが無い環境では透過されない。
- ターミナル・簡易ブラウザ: Windows 11 で WSL2 の起動とコマンド実行・色付き表示、Alt+K の往復、Alt+B で編集中の HTML の表示まで確認。ページ内の Alt+B は合成入力で `keyCode` が届くことまで確認（修正後の往復は未確認）。Linux は型チェックのみ、macOS は型チェックも未実施（C コンパイラが無いため）。
