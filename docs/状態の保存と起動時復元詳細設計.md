# 状態の保存（Alt+Shift+F4）と起動時の復元（Shift 起動）詳細設計

更新用の `--save-and-quit` / `--restore`（基本設計「更新時の保存して終了・状態の復元」）とは別の機能。利用者が操作して状態を残したまま終了し、次の起動で元に戻す。

## 確定事項（2026-11-26 ユーザー確認）

| 項目 | 決定 |
| :--- | :--- |
| 記録する終了 | Alt+Shift+F4 だけ。確認ダイアログを出さずに状態を記録して終了する |
| パスのある未保存ファイル | 上書きしない。編集内容を一時保存し、復元時は元のパス付きの未保存バッファに戻す |
| 復元する起動 | Shift を押したまま起動し、記録が残っていた場合 |
| 複数の vz | vz ごとに記録する（プロセス ID に紐づけ）。Shift 起動 1 回につき、PID の小さい順に 1 つ分を戻す |
| 他の終了 | 状態を記録しない。他の vz の記録は消さない |
| 更新用 | `--save-and-quit` / `--restore`（`session/session.ini`）は今のまま。両者の記録は混ぜない |

## 記録の置き場所

```
<設定フォルダ>/vzeditor/session/saved/
    <pid>/session.ini            … 1 つの vz の状態（形式は更新用の session.ini と同じ）
    <pid>/unsaved-<pid>-<n>.txt
    <pid>/huge-<pid>-<n>.vzedit
    <pid>-<k>/                   … 同じ名前が既にある場合（PID の再利用・復元できずに戻した記録）
    .writing-<pid>/              … 書き込み中
    restoring-<pid>-<時刻>/       … 復元中
```

- 対象にするのは `<pid>` / `<pid>-<k>` の名前で `session.ini` があるフォルダだけ。並び順は `(pid, k)` の数値順（`k` 無しは 0）。
- 書き込みは `.writing-<pid>` で行う（始める前に同名のフォルダを消す）。書き終えたら `<pid>`（ふさがっていれば `<pid>-<k>`）へ改名して公開する。公開が最後の手順で、公開した後は必ず終了する。そのため、終了時に自分の記録を消す処理は持たない。
- 改名は Windows で一時的に失敗することがあるので、100 ms 間隔で 3 回まで試す。

## 記録形式の拡張（更新用と共通）

- `temp` 欄にはファイル名だけを書く。読むときは `session.ini` があるフォルダからの相対で解決する（絶対パスはそのまま使う。古い記録との互換）。これにより、フォルダを改名しても一時保存を参照できる。
- `crlf` 欄を `改行[;文字コード[;更新時刻ns;長さ]]`（例 `1;Shift_JIS;1732600000000000000;1234`）に拡張する。古い形式の `0` / `1` も読める。
- `Unsaved` の復元では文字コードとディスクの状態（`disk_stamp`）を戻す。閉じている間にファイルが外部で変更されていた場合は、起動後に既存の再読み込み確認（ConfirmReload）で気付ける。既存の `--restore` で文字コードが UTF-8 になってしまう問題も、これで直る。

## 処理

### 保存（Alt+Shift+F4）

1. 入口（どれも `save_state_and_quit` を呼ぶ）
   - キー: `window_style_key_action` の Alt+Shift 系に F4 を加え、`MenuAction::SaveStateAndQuit` を返す（両方式共通）。キーはモーダル表示中も受け付ける。`update` の中で `handle_events` の前に Alt+Shift+F4 の押下だけを先に見る。
   - OS の閉じる要求: Windows は Alt+Shift+F4 でも OS が `close_requested` を出す見込み（実機で確認する）。`handle_close_request` では、`close_requested` を確かめた直後、未保存の判定より前に Alt+Shift の判定を置く。判定は、そのフレームの F4 の押下、egui の修飾キー、OS のキー状態（`vz_platform::keyboard::alt_shift_held`。Windows のみ）のどれか。WebView にフォーカスがあると、キーは egui に届かないため OS のキー状態も見る。
   - メニュー「ファイル」に「状態を記録して終了（Alt+Shift+F4）」を追加する。
2. `save_state_and_quit` の流れ
   - `allow_close` が立っていれば何もしない（同じフレームでの二重の記録を防ぐ）。
   - 記録には `save_session_to(&writing_dir, SaveMode::KeepUnsaved)` を使う。既存の関数に保存方式の引数を加え、更新用は `SaveMode::SaveFiles` を渡す（今の動作）。`KeepUnsaved` の違い:
     - パスのある未保存（巨大でない）: 保存せず `EntryKind::Unsaved`（`path`・文字コード・`disk_stamp` 付き）として一時保存する。
     - 巨大ファイルの未保存: 保存せず `write_huge_edits` で `EntryKind::HugeEdits` にする。
     - 外部変更との衝突の判定は行わない（上書きしないので不要）。確認待ちの `Conflict` はそのまま記録する。
   - 巨大ファイルの保存中（`huge_save`）・すべて置換の実行中（`huge_replace`）は記録しない。理由を表示して終了を中止する（更新用も同じ条件にする）。
   - 保存ダイアログ・確認ダイアログの表示中や、保存して終了の途中でも記録する。未保存の内容は一時保存に残るので失われない。
   - 失敗したら `.writing-<pid>` を消し、`CancelClose` を送ってステータスに理由を表示する。成功したら公開して `close_now`。

### 復元（Shift 起動）

1. Shift の判定（`vz_platform::keyboard::shift_held() -> Option<bool>`）
   - Windows: `GetAsyncKeyState(VK_SHIFT)`。macOS: `CGEventSourceFlagsState`（CoreGraphics を framework としてリンク）。
   - その他（Linux）は `None` を返す。その場合、アプリは起動後 1 秒までのフレームの `modifiers.shift` で判定する（winit はフォーカスを得たときに修飾キーを同期する）。
   - `--restore` を指定したときは更新用の復元を優先し、Shift は見ない。Ctrl+Shift も Shift として扱う。
2. `session::take_saved_state(dir) -> Option<SavedState>`（vz-config）
   - 候補を順に `restoring-<自分の pid>-<時刻>` へ改名し、最初に成功したものを使う（同時に起動した vz が同じ記録を取らないため）。
   - `session.ini` を読む。この時点では消さない。
3. `restore_entries(&restoring_dir, entries)` でバッファを作る（既存の `restore_session_from` の本体を分けたもの。`temp` はフォルダからの相対で解決する）。
   - すべて作り終えてからフォルダを消す。
   - 戻せなかった巨大ファイルの編集は、その項目だけを書いた `session.ini` と一緒に残し、数値名（`<pid>-<k>`）に戻して再公開する（次の Shift 起動で再試行できる）。
4. 引数のファイルは復元の後に開く（`--restore` と同じ順）。記録が無ければ通常の起動になる。

## ウィンドウの位置・仮想デスクトップの記録と復元（追加設計）

### 確定事項（2026-11-26 依頼・レビュー反映）

| 項目 | 決定 |
| :--- | :--- |
| 対象 | 状態の記録（Alt+Shift+F4 / `--save-and-quit`）と復元（Shift 起動 / `--restore`）で、ウィンドウの位置・サイズと仮想デスクトップも戻す |
| 記録の分け方 | `session.ini` に物理モニター（位置・サイズ・拡大率・最大化・モニター名）の `monitor` 行と、仮想デスクトップの `desktop` 行を別々に書く |
| 仮想デスクトップの管理 | vz-platform の `virtual_desktop` モジュール（egui に依存しない）。VZ 本体は OS 非依存の `VirtualDesktopManager` だけを使う |
| 取得・移動に失敗したとき | 無理に進めない。`desktop` 行を書かない／移動しないだけで、ほかの記録・復元は今までどおり行う（エラーで記録や終了を中止しない。再試行しない） |
| 通常の起動 | `settings.ini` の位置で起動し、仮想デスクトップは移動しない（今いるデスクトップに開く） |
| 複数の vz の `--save-and-quit` | 1 つのウィンドウにまとめて戻すので、先頭の vz の位置とデスクトップを使う |

### 構成

```
vz-ui（egui）
  restore.rs   記録: capture_session_window → SessionWindow を session.ini へ
               復元: apply_session_window → pending_window_restore / pending_desktop_restore
  window.rs    restore_window_position（サイズ・最大化解除も合わせる）、restore_desktop（表示後に 1 回だけ）
      │ NativeWindow（eframe::Frame の生ハンドルから作る）
      ▼
vz-platform::virtual_desktop   VirtualDesktopManager（取得 desktop_of・復元 restore）
  Windows      IVirtualDesktopManager（COM の公開 API）
  Linux X11    EWMH の _NET_WM_DESKTOP（x11rb で別接続）
  macOS Spaces・Linux Wayland   公開 API が無いため非対応（常に None / false）
vz-platform::monitor   monitor_name（記録用のモニター名。Windows のみ）
vz-config::session     MonitorState / DesktopState / SessionWindow の読み書き（vz-platform に依存しない）
```

OS 依存は `virtual_desktop` の中の `#[cfg]` に閉じ込め、vz-ui は `Option` と `bool` だけを扱う。

### vz-platform: `virtual_desktop`

```rust
/// OS のウィンドウ（Windows: HWND、X11: Window ID）
pub struct NativeWindow(..);
impl NativeWindow {
    /// 扱えないハンドル（Wayland・macOS など）は None
    pub fn from_handle(h: &impl raw_window_handle::HasWindowHandle) -> Option<Self>;
}

/// 仮想デスクトップ（記録・復元に使う値）
pub struct VirtualDesktop {
    /// 取得した仕組み（"windows" / "x11"）。違う仕組みの記録は戻さない
    pub backend: String,
    /// Windows: GUID（`{XXXXXXXX-...}`）、X11: 0 始まりのデスクトップ番号
    pub id: String,
    /// 名前（分かれば。X11 のみ）
    pub name: Option<String>,
}

pub struct VirtualDesktopManager { .. }   // 使うときに作り、使い終えたら捨てる
impl VirtualDesktopManager {
    pub fn new() -> Self;   // 失敗しない（使えなければ内部で無効）
    /// 取得。使えない・失敗は None
    pub fn desktop_of(&self, w: &NativeWindow) -> Option<VirtualDesktop>;
    /// 復元（移動）。仕組みが同じで、移動できたときだけ true
    pub fn restore(&self, w: &NativeWindow, saved: &VirtualDesktop) -> bool;
}
```

- 保存（ファイルへの書き込み）は vz-config の `session.ini` が受け持つ。`VirtualDesktop` ⇔ `session::DesktopState` の変換は vz-ui で行う。
- パニックせず、待ちや再試行もしない。

#### Windows（COM）

- 取得: `IVirtualDesktopManager::GetWindowDesktopId(hwnd)`。`GUID_NULL`・失敗は `None`。
- 移動: `MoveWindowToDesktop(hwnd, &guid)`（自プロセスのウィンドウなので公開 API で動く）。記録したデスクトップが削除されていれば失敗が返るので、それで判定する（レジストリは読まない）。移動前に `GetWindowDesktopId` が同じなら何もせず false。
- 未公開の `IVirtualDesktopManagerInternal`（デスクトップの切り替え・作成）は使わない。そのため移動しても、表示中のデスクトップは切り替わらない。
- COM: UI スレッドで `CoInitializeEx(COINIT_APARTMENTTHREADED)` を呼ぶ（winit が OLE を初期化済みなら `S_FALSE`）。`S_OK` / `S_FALSE` なら Drop で `CoUninitialize`、`RPC_E_CHANGED_MODE` なら呼ばずに続ける。インターフェースは `CoUninitialize` より先に解放する。`CoCreateInstance` が失敗したら（エクスプローラーが動いていない等）無効。
- GUID の文字列は windows-core の `GUID::try_from(&str)`（波括弧なし）で変換し、記録には `{...}` で書く。CLSID の定数 `VirtualDesktopManager` は自作の型と名前がぶつかるので `as` で別名にする。
- 依存: `windows`（0.62。webview2-com が既に使っている版）の `Win32_UI_Shell`・`Win32_System_Com`・`Win32_Foundation`。

#### Linux X11（EWMH）

- `NativeWindow` は `RawWindowHandle::Xlib` / `Xcb` のウィンドウ ID。`DISPLAY` に x11rb（純 Rust の接続）で別に接続する。
- 使える条件: ルートの `_NET_SUPPORTED` に `_NET_WM_DESKTOP` がある（ウィンドウマネージャーが対応していなければ無効）。
- 取得: ウィンドウの `_NET_WM_DESKTOP`（`0xFFFFFFFF` = 全デスクトップに表示は `None`）。名前は `_NET_DESKTOP_NAMES`（NUL 区切り UTF-8）の該当番号。
- 移動: 番号が `_NET_NUMBER_OF_DESKTOPS` 未満なら、ルートへ `_NET_WM_DESKTOP` の ClientMessage（`SubstructureRedirect|SubstructureNotify`、source = 1）を送り flush する。範囲外は false。
- 依存: `x11rb`（0.13。winit が既に使っている版）を Linux だけに追加。

#### macOS Spaces・Linux Wayland

- 公開 API が無い（macOS は非公開の CGS API しかなく、近年は他の Space への移動もできない。Wayland はクライアントからワークスペースを指定するプロトコルが無い）ため、取得は `None`、復元は false。後で対応する場合も、このモジュールの中だけを変える。

### vz-platform: `monitor` の追加

```rust
/// rect（物理ピクセル）が一番重なるモニターの名前（Windows: `\\.\DISPLAY1` など）。他 OS は None
pub fn monitor_name(rect: [i32; 4]) -> Option<String>;
```

- 記録に残すだけで、復元の位置の補正には使わない（ドックの抜き差しで番号が変わり、誤って補正しうるため）。位置は既存の「タイトルバーが見えなければ主モニターの中央」に任せる。

### vz-config: 記録形式

`session.ini` に次の行を加える。1 つの vz につき `monitor` 行を 1 行、続けてその直後に（取得できたときだけ）`desktop` 行を書く。

```
monitor	<x>	<y>	<width>	<height>	<scale>	<maximized>	<モニター名>
desktop	<backend>	<id>	<名前>
```

- `monitor` の値は `settings.ini` の `WindowGeometry` と同じ意味。モニター名が取れなければ空。
- 名前の欄はタブ・改行を空白に置き換えて書く。
- 読むときは最初の `monitor` 行を使い、`desktop` 行はその直後にあるものだけを使う（複数の vz の追記で、別の vz の位置とデスクトップを組み合わせないため）。`monitor` 行が無い記録は `desktop` も使わない。
- 古い版の `parse` は種類 `monitor` を読み飛ばし、`desktop` 行は欄数が違うので読み飛ばす。新しい版で古い記録を読むと、どちらも無し（今までどおり）。
- 型（vz-config::session）:
  - `MonitorState { geometry: WindowGeometry, name: Option<String> }`
  - `DesktopState { backend: String, id: String, name: Option<String> }`
  - `SessionWindow { monitor: Option<MonitorState>, desktop: Option<DesktopState> }`
- `append_session(dir, entries, window: &SessionWindow)`、`parse_window(text) -> SessionWindow`。`take_session` は `(Vec<SessionEntry>, SessionWindow)` を返し、`SavedState` に `window: SessionWindow` を加える。
- `finish_saved_state` で戻せなかった項目を再公開するときは、ウィンドウの行は書かない。

### vz-ui: 記録

- `update` の最初で、`native_window` が無ければ `frame` から `NativeWindow::from_handle` で作って持つ。
- `save_session_with` が `capture_session_window()` で作った `SessionWindow` を `append_session` に渡す:
  - `monitor`: `self.window_geometry`（`track_window_geometry` で更新済み）と `monitor::monitor_name`。位置が無ければ行を書かない。
  - `desktop`: `native_window` があれば `VirtualDesktopManager::new().desktop_of(..)`。`None` なら行を書かない（記録は続ける）。

### vz-ui: 復元

1. `restore_session_from` / `restore_saved_state_from` で `SessionWindow` を受け取り、`apply_session_window` に渡す。項目が空のとき早く戻る `restore_entries` の外で呼ぶ。
2. 物理モニター: `window_geometry` と `pending_window_restore` を記録の値にし、再描画を要求する（Linux の Shift 判定は `restore_window_position` より後で動くため）。`restore_window_position` は今までの処理に次を加える:
   - 内側のサイズ: `g.width * g.scale / 今の ppp`（ポイント）に換算し、今と違えば `InnerSize` を送る（最大化より先）。
   - 最大化: 記録が最大化なら `Maximized(true)`、記録が最大化でなく今が最大化なら `Maximized(false)`。
3. 仮想デスクトップ: `pending_desktop_restore: Option<DesktopState>` に置く。eframe（glow）は最初の描画の後でウィンドウを表示するので、描画 2 フレーム目以降で `native_window` があるときに `VirtualDesktopManager::restore` を 1 回だけ呼び、結果にかかわらず `None` に戻す。残っている間は再描画を要求する。
   - 移動できたときだけ、ステータスの末尾に「（別の仮想デスクトップへ移動しました）」を加える。それ以外は何もせず、今のデスクトップのまま。
4. 通常の起動と引数のファイルだけの起動では、仮想デスクトップに触れない。

### 失敗時の扱い（まとめ）

| 場面 | 動作 |
| :--- | :--- |
| COM / X11 に接続できない・ハンドルが無い（Wayland・macOS 含む） | `desktop` 行を書かない。記録・終了は続ける |
| 記録したデスクトップが無い・仕組みが違う | 移動しない。位置とバッファは戻す |
| 移動の API が失敗 | 1 回で諦め、今のデスクトップのまま |
| 記録の位置がどのモニターにも見えない | 主モニターの中央（既存の処理） |
| `monitor` / `desktop` 行が無い古い記録 | 今までどおり（`settings.ini` の位置、今のデスクトップ） |

### テスト

- vz-config: `monitor` / `desktop` 行の読み書き（日本語の名前、タブ・改行の置き換え）、行が無い古い記録、`parse` が項目だけを返すこと、`monitor` の直後でない `desktop` を使わないこと、再公開でウィンドウの行が消えること。
- vz-platform: GUID と記録の文字列の変換、`_NET_DESKTOP_NAMES` の分割（純粋な関数に分けて試す）。`VirtualDesktopManager::new()` がパニックしないこと。
- vz-ui: 仮想デスクトップが取れない（テストのアプリはウィンドウが無い）状態で記録・復元してもバッファが戻ること、`monitor` 行が `pending_window_restore` に入ること。
- 実機（Windows）: デスクトップ 2 で Alt+Shift+F4 → デスクトップ 1 で Shift 起動 → ウィンドウがデスクトップ 2 へ移ること。デスクトップ 2 を削除してから戻すと、今のデスクトップに開くこと。2 台目のモニター上で記録して戻すこと。「すべてのデスクトップに表示」にしたウィンドウの取得結果。

### 戻らないもの・未確認

- 移動先のデスクトップへ表示を切り替えることはしない（Windows の公開 API に無い）。Shift 起動したデスクトップからはウィンドウが消える。
- macOS・Wayland は仮想デスクトップを戻さない。X11 は WSLg（Wayland）では使えないので、X11 デスクトップの実機での確認が必要。
